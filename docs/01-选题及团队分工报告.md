## 一、选题背景与意义

《专业综合实践》是通信工程（计算机网络通信）专业的总结性实践环节，要求综合运用三年所学的软件工程、Java 程序设计与 Android 开发知识，完成一个移动互联系统从选题、方案设计、开发实现到答辩的全过程。

本课程教学大纲给出的参考选题中明确包含「**运动打卡社交移动端系统**」与「**移动端离线‑在线数据同步系统**」两个方向。本组选择将两者结合：以健身打卡为业务核心，向上构建好友动态、点赞、关注、排行榜等社交能力，向下构建「本地优先、云端同步」的离线‑在线数据同步机制。该选题同时贴合「网络通信」专业方向——客户端与服务端之间的 HTTP/REST 协议设计、数据同步策略正是本专业知识的直接应用。

**选题意义：**

1. **工程能力**：完整实践 C/S 架构系统的需求分析、协议设计、编码实现与联调测试；
2. **专业贴合**：网络协议设计、数据同步、弱网降级策略均属于计算机网络通信的核心问题；
3. **使用价值**：面向真实运动记录场景，具备可用性与一定的社会健康价值。

## 二、选题初步分析

### 2.1 同类产品与文献调研（初步）

| 产品/方案 | 主要能力 | 不足（本项目的改进空间） |
| --- | --- | --- |
| Keep | 训练课程 + 运动记录 + 社区 | 功能庞大、依赖商业云服务，无法作为课程自研复现 |
| 悦跑圈 | 跑步记录 + 跑团社交 + 排行榜 | 侧重跑步单项，且需账号体系绑定手机号与云端 |
| 小米运动健康 | 多设备数据接入、界面精致 | 强依赖小米硬件生态，服务端不可控 |
| GitHub 开源健身类项目（搜索调研） | 多为纯本地记录类 App | 缺失服务端与社交闭环，或工程结构不完整 |

初步结论：现有方案要么过于商业化、依赖不可控云服务，要么为纯本地工具、缺少「移动互联」属性。**自研一套「轻量服务端 + 离线优先客户端」的完整系统**既满足课程要求，也具备清晰的工程可解释性。

### 2.2 拟解决的核心问题

1. 运动打卡数据在**弱网/断网**环境下如何不丢失、恢复网络后如何自动同步；
2. 多用户场景下如何设计**轻量 REST 协议**支撑排行榜、动态流、点赞与关注；
3. 如何在有限的开发周期内保证**工程质量**（密码安全存储、参数化查询、自动化测试）。

### 2.3 技术方向初选

- 客户端：Android（Java），沿用先修课「Android 开发技术」技术栈；
- 服务端：Java 轻量 Web 框架（Javalin） + SQLite；
- 协议：HTTP + REST + JSON；
- 存储：客户端本地 SQLite 作为离线事实来源，服务端 SQLite 作为云端共享数据源。
