## 摘要

本项目面向个人运动记录与好友监督激励场景，设计并实现了一套「Android 客户端 + Javalin REST 服务端」的移动互联系统。系统以运动打卡为业务核心，提供计时记录、数据统计、连续打卡、勋章激励等功能，并构建了排行榜、好友动态、点赞与关注等社交闭环。针对弱网与断网场景，系统采用「本地优先、异步上云」的离线‑在线数据同步机制，保证打卡数据零丢失。网络层采用 HTTP + REST + JSON 协议，服务端提供 12 个 API 端点；密码使用 PBKDF2 加盐哈希存储，所有数据库访问参数化。系统通过 11 项 API 集成测试与真机/模拟器联调验证，功能与性能达到设计要求。

**关键词：** 移动互联；Android；REST；离线同步；社交；Javalin；SQLite

## 第三章 系统设计

> 完整设计见《项目总体设计方案》，本章概述关键设计决策。

### 3.1 总体架构

系统采用 C/S 架构，客户端分为 UI 层、业务层、网络层（ApiClient）、本地存储层（SQLite）；服务端分为路由层（Main）、业务层（FitnessService）、数据层（Database）。客户端本地库是打卡数据的第一事实来源，服务端承载账号与多用户共享数据。

### 3.2 网络协议

HTTP/1.1 + REST + JSON（UTF-8）。统一响应约定：`code==0` 为成功；错误返回对应 HTTP 状态码与 `{code,message}`。数组型接口直接返回 JSON 数组。共 12 个 API 端点（注册、登录、改密、打卡上报/删除/清空、排行榜、动态流、点赞、关注、搜索、关注列表、连通测试），详见 `server/README.md`。

### 3.3 技术选型

| 决策点 | 选择 | 主要理由 |
| --- | --- | --- |
| 服务端框架 | Javalin 6 | 轻量、启动快、HTTP 语义透明，便于讲解 |
| 客户端网络 | HttpURLConnection + org.json | Android 内置零依赖，协议细节可控可测 |
| 服务端存储 | SQLite（单文件） | 零安装、与客户端技术同源 |
| 密码安全 | PBKDF2WithHmacSHA256 + 随机盐 | JDK 内置、抗彩虹表 |
| 实时性 | REST 轮询（15 s）+ 下拉刷新 | 满足秒级体验，实现复杂度可控 |
| 动画 | Lottie | 矢量、体积小、效果佳 |

## 第四章 系统实现

### 4.1 离线‑在线数据同步

打卡保存采用「**本地事务优先**」：先写入本地 SQLite 并立即反馈用户，再在后台线程调用 `POST /api/records` 上云。上云失败仅提示「已保存本地」，不阻塞操作、不丢数据；页面恢复时轮询/刷新间歇重试。该机制使系统在断网、弱网场景下保持完整可用性。

### 4.2 在线认证与离线降级

登录优先请求服务端（5 s 连接超时）；网络不可达时回退本地数据库校验（PBKDF2 哈希比对，兼容旧版明文并自动升级为哈希）。注册采用「服务端 + 本地双写」；服务器不可达时降级为纯本地注册。该设计保证演示与使用不依赖网络状态。

### 4.3 社交功能实现

- **排行榜**：服务端以「时间窗参数」在同一 SQL 中切换本周榜/总榜，保证聚合口径一致；
- **好友动态流**：`WHERE username=? OR username IN (SELECT followee FROM follows WHERE follower=?)`，天然实现「只看已关注者」；取消关注后动态即时消失，配套「发现好友」搜索入口（搜索接口直接返回 `following` 字段，关注状态实时准确）；
- **点赞幂等**：`likes` 表唯一约束 `(record_id, username)`，接口语义为 toggle，重复请求结果稳定。

### 4.4 客户端网络层封装

`ApiClient` 基于 `HttpURLConnection` 实现：后台线程池执行请求 → UTF-8 编解码 → JSON 解析 → 主线程回调 UI。统一区分「网络不可达」与「业务失败」两类错误，支撑上层离线降级逻辑。

### 4.5 性能优化

| 优化项 | 措施 | 效果 |
| --- | --- | --- |
| 主线程 IO | 数据库查询/聚合移入后台线程（Bg 工具类），UI 仅做 setText | 页面切换不掉帧 |
| 页面栈管理 | 底部导航使用 `FLAG_ACTIVITY_REORDER_TO_FRONT` 复用实例 | 避免 Activity 栈无限叠加，切换免重建 |
| 首页查询 | 两次全表查询合并为一次（倒序首条即最近记录） | 查询量减半 |
| 刷新节流 | 社区页 15 s 内不重复拉取；页面不可见停止轮询 | 降低无效网络与渲染开销 |
| 弱网体验 | 刷新失败保留旧数据不清空 | 避免白屏 |

### 4.6 情感化交互（Lottie）

登录页跑步循环动画、打卡成功庆祝彩带、点赞爱心爆炸、注册成功打勾，素材为矢量 JSON（KB 级），任意分辨率不失真。动画采用「事件驱动 + 生命周期安全」方式播放（页面不可见即停止）。

### 5.4 数据一致性验证

- 种子数据：8 个用户、27 条打卡记录（横跨 10-07 至 10-24）、关注与点赞关系完整；
- 字符编码：对昵称与运动类型逐字符核验 UTF-8 码点（如「小明」= U+5C0F U+6E05…），确认请求→存储→响应全链路无乱码；
- 榜单口径：本周榜与总榜在同一数据集下呈现不同排名（李嘉阳总榜第 1、本周榜第 2），验证时间窗聚合正确。

### 5.5 性能与稳定性观察

- 页面切换：数据库查询移入后台线程后，切换过程无掉帧（主线程无 IO 阻塞）；
- 弱网：轮询失败时保留既有数据，无白屏/闪退；
- 服务端：11 项集成测试连续重复执行稳定通过；单次测试套件耗时约 3–5 s。

## 第六章 项目总结

### 6.1 主要成果

1. 完成了一套可运行、可演示、可部署的移动互联系统（客户端 + 服务端 + 一键启动脚本）；
2. 实现了离线优先的数据同步与在线社交闭环（排行榜/动态/点赞/关注）；
3. 建立了可验证的测试体系：11 项 API 集成测试 + 真机联调 + 数据一致性核验；
4. 形成了完整的工程文档（README、API 文档、三份课程报告、答辩 PPT）。

### 6.2 创新点

1. **离线优先同步**：本地事务成功即反馈、网络同步异步化，弱网零丢失；
2. **零依赖网络层**：内置 API 手写 REST 封装，协议链路完全可解释、可测试；
3. **轻量实时方案**：轮询 + 刷新节流 + 可见性感知，在无 WebSocket 下实现近实时体验；
4. **情感化交互**：Lottie 矢量动画强化打卡正向反馈。

### 6.3 不足与改进方向

| 不足 | 改进方向 |
| --- | --- |
| API 使用 username 标识会话，未引入 Token | 引入 JWT/会话 Token，接口鉴权 |
| 实时性依赖轮询 | 升级 WebSocket/SSE 推送 |
| 客户端单元测试覆盖不足 | 补充核心算法（连续打卡、同步队列）单测 |
| 头像未上云 | 引入对象存储与图片上传 |
| HTTP 明文传输 | 部署 HTTPS/TLS |
